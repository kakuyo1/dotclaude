0005 · dlsym/dlopen 的 CMake 配置实战

从 CMakeLists.txt 到能跑的 .so + 前端——完整工程配置

前面 四课 讲完了原理和陷阱。这节课把它们全部落地到 CMake 配置上，目标是你能直接复制修改用到自己的项目里。

一、总体结构：两个 CMake 项目的分工

图 1：两个 CMake 项目的职责划分。关键点：前端不链接 libvoice.so，只链接 libdl。编译时没有依赖关系，运行时通过 dlopen 发现。

二、.so 侧：完整的 CMakeLists.txt

这是语音引擎的构建配置——从源码到可安装的 .so。每一行都有注释解释为什么。

# ============================================================
# libvoice/CMakeLists.txt  —— 语音引擎 .so
# ============================================================
cmake_minimum_required(VERSION 3.14)
project(voice VERSION 1.2.0 LANGUAGES C CXX)

# ── 1. 生成导出头文件 ──────────────────────────
# 自动生成 voice_export.h，内容类似：
#   #define VOICE_API __attribute__((visibility("default")))
include(GenerateExportHeader)
# 注意：待会 add_library 之后才调用 generate_export_header

# ── 2. 定义 .so 目标 ──────────────────────────
add_library(voice SHARED
    # 公开 C API 头文件（安装给消费者）
    PUBLIC
        include/voice_c_api.h

    # 实现文件
    PRIVATE
        src/voice_c_api.cpp      # C 桥接层实现
        src/VoiceEngine.cpp      # 你的 C++ 语音引擎
        src/AudioBuffer.cpp
        src/ModelLoader.cpp
)

# ── 3. 生成 VOICE_API 宏 ──────────────────────
generate_export_header(voice
    BASE_NAME voice
    EXPORT_FILE_NAME include/voice_export.h
)
# 产物: ${CMAKE_CURRENT_BINARY_DIR}/include/voice_export.h

# ── 4. 设置符号可见性 ─────────────────────────
set_target_properties(voice PROPERTIES
    # 默认隐藏所有符号
    CXX_VISIBILITY_PRESET hidden
    VISIBILITY_INLINES_HIDDEN  ON

    # 对应 -fvisibility=hidden -fvisibility-inlines-hidden
)

# ── 5. 设置 SO 版本 ───────────────────────────
set_target_properties(voice PROPERTIES
    VERSION  ${PROJECT_VERSION}   # 1.2.0  → 实名 libvoice.so.1.2.0
    SOVERSION 1                   # soname  → libvoice.so.1
)
# CMake 会自动创建符号链接:
#   libvoice.so     → libvoice.so.1
#   libvoice.so.1   → libvoice.so.1.2.0
#   libvoice.so.1.2.0  (真实文件)

# ── 6. 编译选项 ───────────────────────────────
target_compile_features(voice PRIVATE cxx_std_17)
target_include_directories(voice
    PUBLIC
        $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>
        $<BUILD_INTERFACE:${CMAKE_CURRENT_BINARY_DIR}/include>  # voice_export.h 在这里
        $<INSTALL_INTERFACE:include>
    PRIVATE
        src/
)

# ── 7. 链接内部依赖 ───────────────────────────
find_package(Threads REQUIRED)  # 如果内部用了线程
target_link_libraries(voice PRIVATE
    Threads::Threads
    # 其他内部依赖……全部 PRIVATE ——不泄漏给消费者
)

# ── 8. (可选) 版本脚本 ────────────────────────
# 如果你需要符号版本控制，创建一个 libvoice.ver 文件
# target_link_options(voice PRIVATE
#     -Wl,--version-script=${CMAKE_CURRENT_SOURCE_DIR}/libvoice.ver
# )

# ── 9. 安装规则 ───────────────────────────────
include(GNUInstallDirs)

install(TARGETS voice
    EXPORT  voiceTargets
    LIBRARY DESTINATION ${CMAKE_INSTALL_LIBDIR}   # .so 文件 + 符号链接
    ARCHIVE DESTINATION ${CMAKE_INSTALL_LIBDIR}   # 静态库（如果有）
    RUNTIME DESTINATION ${CMAKE_INSTALL_BINDIR}   # Windows DLL
)

install(FILES
    include/voice_c_api.h
    ${CMAKE_CURRENT_BINARY_DIR}/include/voice_export.h
    DESTINATION ${CMAKE_INSTALL_INCLUDEDIR}/voice
)

# ── 10. 导出 CMake 配置（给不用 dlopen 的消费者）──
install(EXPORT voiceTargets
    FILE voiceTargets.cmake
    NAMESPACE voice::
    DESTINATION ${CMAKE_INSTALL_LIBDIR}/cmake/voice
)
第 4-5 步是关键： CXX_VISIBILITY_PRESET hidden + generate_export_header + VERSION/SOVERSION 三个属性一起，让你的 .so 从编译出来的那一刻就是生产级的。不需要手写 -fvisibility=hidden 和 -Wl,-soname。

安装后的目录结构

/usr/local/
├── include/voice/
│   ├── voice_c_api.h
│   └── voice_export.h
└── lib/
    ├── libvoice.so → libvoice.so.1
    ├── libvoice.so.1 → libvoice.so.1.2.0
    ├── libvoice.so.1.2.0
    └── cmake/voice/
        └── voiceTargets.cmake

三、前端侧：完整的 CMakeLists.txt

前端不链接 libvoice.so。它只链接 libdl（提供 dlopen/dlsym/dlclose），然后通过头文件知道 C API 的签名，在运行时自己加载 .so。

# ============================================================
# frontend/CMakeLists.txt  —— Qt 前端
# ============================================================
cmake_minimum_required(VERSION 3.14)
project(my_app VERSION 1.0.0 LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_AUTOMOC ON)

# ── 1. 找到 Qt ─────────────────────────────────
find_package(Qt5 COMPONENTS Core Widgets REQUIRED)

# ── 2. 主程序 ──────────────────────────────────
add_executable(my_app
    main.cpp
    VoiceModuleLoader.cpp   # 封装 dlopen/dlsym 的类
    MainWindow.cpp           # Qt 界面
)

# ── 3. 关键：链接 libdl，不链接 libvoice ──────
target_link_libraries(my_app PRIVATE
    Qt5::Core
    Qt5::Widgets
    ${CMAKE_DL_LIBS}         # 在 Linux 上 = dl
)                             # 在 BSD 上也是 dl
                              # 在 macOS 上为空（dlopen 在 libSystem 中）
                              # 在 Windows 上用这个变量也安全（展开为空）

# ── 4. 可选：把语音头文件路径加入 include ─────────
# 如果你不想复制头文件，直接在源码里 #include 相对路径也可以
# 但为了规范性，建议这样：
target_include_directories(my_app PRIVATE
    ${CMAKE_SOURCE_DIR}/../libvoice/include
)

# ── 5. RPATH 配置 —— 运行时从哪里找 .so ─────────
# 这是最容易出问题的地方，下节单独展开讲
常见错误： 有人会把 libvoice.so 加到 target_link_libraries 中，然后又在代码里用 dlopen——这等于运行时加载了两遍（一次是 linker 在启动时加载的，一次是你的 dlopen），引用计数变成 2，需要 dlclose 两次才能真正卸载。

四、RPATH 配置——让 dlopen 找到 .so

这是 C 桥接层 + dlopen 模式中最容易出问题的地方。dlopen("libvoice.so") 这种相对路径写法在生产环境中几乎一定会失败——因为工作目录不一定是 .so 所在的目录。

问题根源：dlopen 的搜索顺序

① 如果路径包含 /（如 ./libvoice.so 或绝对路径），直接用这个路径
② 搜索 ELF 的 DT_RPATH（编译时写入的 RPATH）——仅当 DT_RUNPATH 不存在时
③ 搜索 LD_LIBRARY_PATH 环境变量
④ 搜索 ELF 的 DT_RUNPATH（编译时写入的 RUNPATH）
⑤ 搜索 /etc/ld.so.cache
⑥ 搜索 /lib 和 /usr/lib

对于 dlopen 场景，你需要确保 libvoice.so.1 在这些搜索路径的某个地方。三种常见策略：

策略 A：RPATH 指向安装目录（推荐用于发布）PRODUCTION
# 可执行文件编译时写入 RPATH
set_target_properties(my_app PROPERTIES
    INSTALL_RPATH "${CMAKE_INSTALL_PREFIX}/${CMAKE_INSTALL_LIBDIR}"
    # 或者相对于可执行文件的位置: $ORIGIN/../lib
    INSTALL_RPATH "$ORIGIN/../lib"
)

# 如果可执行文件在 bin/my_app，.so 在 lib/libvoice.so：
# 最终安装目录:
#   /opt/myapp/bin/my_app      ← RPATH = $ORIGIN/../lib
#   /opt/myapp/lib/libvoice.so.1.2.0
策略 B：硬编码搜索路径（推荐用于开发阶段）DEVELOPMENT
# 开发时在代码中写死 build 目录
void* handle = dlopen(
    "/home/user/project/build/libvoice/libvoice.so", RTLD_NOW);
// 或者从配置文件读路径
// 或者用 CMake 的 configure_file 在编译时注入路径
策略 C：LD_LIBRARY_PATH（推荐用于测试/CI）CI/TEST
# 只在测试脚本和 CI 中使用——生产环境不要依赖环境变量
$ LD_LIBRARY_PATH=/opt/myapp/lib ./my_app
# 或在 CMake 的 ctest 配置中：
# set_tests_properties(my_test PROPERTIES
#     ENVIRONMENT "LD_LIBRARY_PATH=${CMAKE_BINARY_DIR}/libvoice")

五、综合工程：Monorepo 下的 CMake 配置

如果你的 .so 和前端在同一个仓库里（大多数内部项目的实际情况），可以用一个顶层 CMakeLists.txt 统一管理。但关键约束不变：前端仍然不链接 .so。

# ============================================================
# 顶层 CMakeLists.txt
# ============================================================
cmake_minimum_required(VERSION 3.14)
project(voice_assistant VERSION 1.0.0 LANGUAGES C CXX)

# 全局设置
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_VISIBILITY_PRESET hidden)       # 全局默认隐藏
set(CMAKE_VISIBILITY_INLINES_HIDDEN ON)

# ── 语音引擎 .so ──────────────────────────────
add_subdirectory(libvoice)

# ── Qt 前端 ───────────────────────────────────
add_subdirectory(frontend)

# 注意：没有 target_link_libraries(frontend voice)
#       前端通过 dlopen 运行时加载 .so

# 但我们可以添加构建依赖——确保 .so 先于前端编译
# （仅当你在测试中需要运行前端时有用）
add_dependencies(my_app voice)
# ============================================================
# libvoice/CMakeLists.txt（简化版）
# ============================================================
add_library(voice SHARED
    src/voice_c_api.cpp
    src/VoiceEngine.cpp
)

include(GenerateExportHeader)
generate_export_header(voice
    BASE_NAME voice
    EXPORT_FILE_NAME include/voice_export.h
)

set_target_properties(voice PROPERTIES
    CXX_VISIBILITY_PRESET hidden
    VISIBILITY_INLINES_HIDDEN  ON
    VERSION  ${PROJECT_VERSION}
    SOVERSION 1
)

target_include_directories(voice
    PUBLIC  include
    PRIVATE src
)

# 构建后，.so 在 ${CMAKE_BINARY_DIR}/libvoice/libvoice.so.1.2.0
# CMake 同时创建符号链接 libvoice.so.1 和 libvoice.so
开发时的便利技巧： 在 CMake 中 define 一个宏，让前端代码可以找到 build 目录下的 .so： 
# frontend/CMakeLists.txt
target_compile_definitions(my_app PRIVATE
    VOICE_SO_PATH="${CMAKE_BINARY_DIR}/libvoice/libvoice.so"
)

// VoiceModuleLoader.cpp
void* handle = dlopen(VOICE_SO_PATH, RTLD_NOW);
// 编译时 VOICE_SO_PATH 被替换为 .so 的绝对路径
// 只在开发阶段用；发布时改为从安装路径加载

六、VoiceModuleLoader：一个封装 dlopen/dlsym 的 C++ 类

在生产代码中你不会裸调 dlopen/dlsym。下面是一个可以直接用的 RAII 封装——初始化时解析所有函数指针，析构时 dlclose：

// VoiceModuleLoader.h
#pragma once
#include "voice_c_api.h"  // C API 的类型定义
#include <string>
#include <stdexcept>

struct VoiceModule {
    // 函数指针——一次性全部解析并缓存
    VoiceEngineHandle* (*create) (const char*);
    void               (*destroy)(VoiceEngineHandle*);
    int                (*start)  (VoiceEngineHandle*, const char*, int);
    int                (*stop)   (VoiceEngineHandle*);
    const char*        (*version)(void);

    VoiceModule() = default;
    explicit operator bool() const { return create != nullptr; }
};

class VoiceModuleLoader {
public:
    explicit VoiceModuleLoader(const std::string& so_path);
    ~VoiceModuleLoader();

    // 不可拷贝
    VoiceModuleLoader(const VoiceModuleLoader&) = delete;
    VoiceModuleLoader& operator=(const VoiceModuleLoader&) = delete;

    // 可移动
    VoiceModuleLoader(VoiceModuleLoader&& other) noexcept;
    VoiceModuleLoader& operator=(VoiceModuleLoader&& other) noexcept;

    const VoiceModule& api() const { return api_; }

private:
    void*       handle_ = nullptr;
    VoiceModule api_   = {};

    void unload();
};

// VoiceModuleLoader.cpp
#include "VoiceModuleLoader.h"
#include <dlfcn.h>

VoiceModuleLoader::VoiceModuleLoader(const std::string& so_path) {
    handle_ = dlopen(so_path.c_str(), RTLD_NOW);
    if (!handle_) {
        throw std::runtime_error(
            std::string("dlopen failed: ") + dlerror());
    }

    // 一次性解析所有符号——不在任何热路径上调用 dlsym
    #define LOAD_SYM(name) \
        api_.name = reinterpret_cast<decltype(api_.name)>( \
            dlsym(handle_, "voice_engine_" #name)); \
        if (!api_.name) { \
            unload(); \
            throw std::runtime_error( \
                std::string("dlsym failed: voice_engine_") + #name); \
        }

    LOAD_SYM(create);
    LOAD_SYM(destroy);
    LOAD_SYM(start);
    LOAD_SYM(stop);
    LOAD_SYM(version);

    #undef LOAD_SYM
}

VoiceModuleLoader::~VoiceModuleLoader() { unload(); }

void VoiceModuleLoader::unload() {
    if (handle_) {
        dlclose(handle_);
        handle_ = nullptr;
    }
    api_ = {};
}

// 移动构造
VoiceModuleLoader::VoiceModuleLoader(VoiceModuleLoader&& other) noexcept
    : handle_(other.handle_), api_(other.api_) {
    other.handle_ = nullptr;
    other.api_ = {};
}
设计要点回顾： (1) RTLD_NOW——dlopen 时就暴露符号缺失，不放炸弹；(2) 所有函数指针一次性解析——dlsym 有哈希查找+锁开销，不能放热路径；(3) RAII 管理 handle 生命周期——不依赖调用方记得 dlclose；(4) 移动语义——可以放进容器或作为成员变量传递所有权。

七、常见配置错误排查表

现象最可能的原因修复
dlopen: cannot open shared object file .so 不在搜索路径中 检查 RPATH / LD_LIBRARY_PATH / 绝对路径。用 ldd ./my_app 看 RPATH 是否写入了。
dlsym: undefined symbol 符号被 visibility=hidden 隐藏了 检查该函数是否有 VOICE_API 宏。用 nm -D libvoice.so | grep 函数名 验证。
dlsym: undefined symbol（但 nm -D 能看到） extern "C" 忘记了——符号名被 mangle 了 用 nm -D libvoice.so | grep 函数名 看输出。如果有 _Z 前缀就是 name mangling 还在。
dlopen 成功后 dlsym 返回 NULL 符号名拼写不匹配（大小写、前缀等） 用 nm -D 确认确切的符号名字符串，逐字符对比。
dlclose 后 crash 还有线程在使用 .so 中的代码/数据 确保所有使用 .so 中资源的线程已 join，或永远不 dlclose（接受泄漏）。
生成的 voice_export.h 路径找不到 generate_export_header 的产物在 build 目录 记得在 target_include_directories 中加 $<BUILD_INTERFACE:${CMAKE_CURRENT_BINARY_DIR}/include>
VERSION/SOVERSION 设置了但没看到符号链接 只有 make install 后才创建符号链接 build 目录下确实只有实名文件。符号链接是 install 步骤创建的。这不是 bug。

自测

问题 1：CMake 中 CXX_VISIBILITY_PRESET hidden 等效于哪个编译器选项？

A. -fPIC
B. -fvisibility=hidden
C. -fvisibility-inlines-hidden
D. -Wl,--exclude-libs,ALL

问题 2：前端 CMakeLists.txt 中正确的链接方式是什么？

A. target_link_libraries(my_app PRIVATE voice)
B. target_link_libraries(my_app PRIVATE dl) 或 ${CMAKE_DL_LIBS}
C. 不需要链接任何库——dlopen 是系统调用
D. target_link_libraries(my_app PRIVATE voice dl)

问题 3：设置了 SOVERSION 1 和 VERSION 1.2.0 后，make install 创建的符号链接链是什么？

A. libvoice.so → libvoice.so.1.2.0 和 libvoice.so.1.2.0
B. libvoice.so → libvoice.so.1 → libvoice.so.1.2.0
C. libvoice.so.1.2.0 → libvoice.so
D. 只有 libvoice.so.1.2.0——符号链接需要手动创建
